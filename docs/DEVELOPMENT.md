# Разработка и тестирование NYVERRA

В этом документе описан путь от свежего клона до проверки игрового прототипа. **Текущая Alpha 0.61 не является готовым релизом.**

## Требования

- Windows 10/11, Unreal Engine **5.8**.
- Visual Studio с установленными компонентами **Desktop development with C++** и **Game development with C++** (поддержка сборки Unreal).
- Git, Python 3 с командой `py -3`.
- Достаточно места для папок Unreal `Intermediate/`, `Binaries/` и `DerivedDataCache/` (они не входят в Git).

## Быстрый запуск

```bat
git clone https://github.com/Zeihos/NYVERRA-Echo-Frontier.git
cd NYVERRA-Echo-Frontier
py -3 -m unittest discover -s Tools -p "test_alpha_*.py" -v
TEST_ALPHA_061_WINDOWS.bat
```

Последняя команда запускает Python-проверки и сборку `NYVERRAEditor` с использованием установленного UE5.8. При нестандартном пути движка:

```bat
TEST_ALPHA_061_WINDOWS.bat "D:\Epic Games\UE_5.8"
```

Если скрипт сообщает об ошибке — не считайте проект собранным; приложите журнал `BUILD_ALPHA_051.log` и соответствующие ошибки (без секретов и личных данных).

## Первый игровой уровень

**Проверенный** `Content/Maps/TestWorld.umap` ещё не хранится в репозитории. На локальном ПК можно использовать:

```bat
BUILD_AND_PREPARE_ALPHA_053_WINDOWS.bat
```

Скрипт создаёт тестовый уровень только при его отсутствии и настраивает стартовую карту. Это не заменяет проверенную авторскую карту и импорт её зависимых `.uasset` файлов.

При наличии проверенной локальной карты воспользуйтесь `Tools/Sync-TestWorld-ToGitHub.ps1`, внимательно сверив целевой репозиторий и существующие файлы.

Импорт и тестовая карта описаны в [VISUAL_POLISH_056_STATUS.md](../VISUAL_POLISH_056_STATUS.md). Для материалов нужны исходные PNG; наличие скриптов импорта в GitHub **не означает**, что материалы уже готовы к использованию.

## Тестирование

1. **Офлайн-тесты:** `py -3 -m unittest discover -s Tools -p "test_alpha_*.py" -v`.
2. **Компиляция UE:** `TEST_ALPHA_061_WINDOWS.bat`.
3. **Одиночный запуск:** вход на сохранённую карту и проверка управления/ресурсов.
4. **2-player PIE:** движение, репликация, PvP/PvE, строительство, двери. PIE *не проверяет* постоянные сохранения.
5. **Standalone / сервер:** сохранение, выключение сервера, повторный запуск, восстановление мира по [Alpha 0.61 QA](../ALPHA_061_QA.md).
6. **Windows packaged build:** отдельная проверка после успешных предыдущих этапов.

GitHub Actions запускает **только офлайн-тесты**; зелёный статус не подтверждает запуск Unreal Engine.

## Принципы изменений

Изменяйте игру на отдельной ветке и проверяйте, что новые файлы не стирают старую карту, сохранения или материалы. Не добавляйте `Saved/`, `Binaries/`, `Intermediate/`, ключи, локальные конфигурации и личные данные. Для игровых изменений пишите регрессионные тесты; для графики подтверждайте загрузку и результат скриншотами в UE5.8.

У старых Windows-скриптов остались суффиксы версии (например, `BUILD_ALPHA_051_WINDOWS.bat`). Они сохранены ради обратной совместимости, даже если вызываются новыми скриптами.
