# NYVERRA — Alpha 0.62: сохранение персонажей

**Статус:** исходники в `main`. Требуется компиляция в Unreal Engine 5.8 и тесты после перезапуска сервера.

## Реализовано

- Создан `UNyPlayerSaveGame` отдельно от `UNyBaseSaveGame`. Данные баз Alpha 0.60–0.61 не изменяются.
- Сохраняются инвентарь (не более 16 слотов, предметы 0–6, стопки 1–100, инструменты по 1), здоровье, голод, жажда, выносливость, число смертей и флаг смерти.
- При загрузке сервер строго проверяет версию файла, карту, хеш владельца, значения характеристик, допустимые предметы и размер инвентаря.
- Для игрока используются два файла A/B `NYVERRA_Player_v1_<hash>.sav` и `NYVERRA_Player_v1_<hash>_B.sav`. Слот генерируется из карты и серверного идентификатора; хеш не является средством аутентификации.
- При перезапуске выбирается самая новая корректная версия. Если обе копии повреждены, сервер не перезаписывает их.
- После записи выполняется обратное чтение и сравнение версии, предметов, характеристик и ключа владельца.
- Выход игрока вызывает немедленное сохранение; активным игрокам доступно автосохранение каждые 60 секунд. Группировка частых изменений — через 20 секунд.
- Прогресс **не загружается повторно при возрождении**: старые предметы нельзя вернуть после смерти. При отключении во время смерти инвентарь не сохраняется.
- Два одновременно подключённых персонажа с одинаковым серверным идентификатором блокируют запись в свой общий слот до перезапуска.
- В PIE сохранение на постоянный диск выключено, как и для ранее реализованных баз.

## Политика идентификации (важно)

**Standalone:** один локальный пользователь может сохранять прогресс без онлайн-сервиса.

**Listen/Dedicated server:** по умолчанию сохранение прогресса игроков **выключено**. Для включения нужен реально аутентифицированный провайдер OnlineSubsystem и явный аргумент запуска сервера:

```text
-NyAllowAuthenticatedPlayerSaves
```

**Не включайте этот флаг на Null/LAN-сервере:** сетевой ID без подтверждённой аутентификации не защищает чужой инвентарь. Игрок не может выбрать владельца или содержимое сохранения через клиентский RPC. После включения сохранение привязывается к уникальному сетевому ID на стороне сервера, а не к никнейму.

## Как проверить на Windows

В корне Git-клона:

```bat
git pull origin main
CHECK_PROJECT_WINDOWS.bat
```

Сначала скрипт проверит Python, структуру и регрессионные тесты. Затем попытается собрать `NYVERRAEditor` через Unreal Engine 5.8. Для нестандартного пути движка можно передать аргумент `CHECK_PROJECT_WINDOWS.bat "D:\Epic Games\UE_5.8"`.

Перед проверками сохранений **остановите сервер** и создайте резервную копию `Saved/SaveGames/` вне рабочей директории.

## Приёмочные сценарии (реальная игра, не статический тест)

1. Запустить сохранённую карту в **Standalone**, собрать дерево, камень и воду, сделать топор, получить урон, дождаться снижения голода/жажды.
2. Закрыть игру штатно, запустить снова. Убедиться, что количество каждого предмета, здоровье, голод, жажда, выносливость и число смертей восстановились.
3. После первой записи изменить инвентарь, дождаться автосохранения, проверить существование обоих слотов A/B и их чередование.
4. На **копии** данных повредить последний слот и проверить откат к предыдущему корректному снимку. При повреждении обоих файлов — отсутствие перезаписи.
5. Умереть с предметами и отключиться до возрождения: после входа предметы не должны возвращаться.
6. После обычного возрождения собрать новые предметы. Убедиться, что инвентарь не восстанавливается повторно из снимка до смерти.
7. В PIE выполнить идентичные действия: постоянные файлы `Saved/SaveGames/` не должны измениться.
8. На выделенном сервере с реальным проверенным провайдером запустить игру **без** `-NyAllowAuthenticatedPlayerSaves`. Сервер не должен создавать игровые сохранения аккаунтов.
9. Под контролем администратора включить флаг при реальной аутентификации. Подключить двух разных игроков, сохранить разное содержимое, переподключить каждого, подтвердить отсутствие смешивания инвентарей.
10. Проверить два параллельных подключения одного аккаунта (при возможности тестового стенда): сервер должен заблокировать запись спорного слота.
11. Ограничить права записи на тестовой директории сохранений. После ошибки записи прошлый корректный файл должен остаться нетронутым; сервер должен записать ошибку в журнал.
12. Проверить отдельно сборку `NYVERRAServer` и Windows-пакет. Успешный `NYVERRAEditor` сам по себе ещё не означает готовый сервер.

## Ограничения

- В среде ChatGPT **нет Unreal Engine 5.8 и проверенной карты игры**, поэтому настоящее сохранение, C++-компиляция, репликация и загрузка клиента ещё не подтверждены.
- Система сохраняет инвентарь и параметры **только на текущей карте**. Переходы между картами, общие аккаунты, персонажи нескольких серверов, торговля, базы клана и сезонные вайпы — отдельная задача.
- Сохранение A/B уменьшает вероятность полной потери файла, но **не заменяет резервные копии**.
- Хеш в имени файла не скрывает логическую принадлежность и не защищает от взлома сервера.
- Если диск недоступен, новые изменения в игре могут продолжиться, но прогресс не будет гарантированно сохранён. Сервер пишет ошибку и блокирует повторное использование повреждённого слота до перезапуска.
- Файлы `Saved/` исключены из Git: не публикуйте приватные сохранения и журналы с идентификаторами игроков.
