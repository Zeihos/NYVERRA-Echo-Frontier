# NYVERRA: Echo Frontier — Alpha 0.60

**Дата:** 17 ноября 2026 • **Репозиторий:** `Zeihos/NYVERRA-Echo-Frontier` (Private), ветка `main`.

## Что внесено в проект

Появилась первая серверная система постоянного сохранения **построек**: фундаменты, стены и двери.

- Новые C++-классы `UNyBaseSaveGame` и `FNySavedBuildPiece` (`Source/NYVERRA/Public/NyBaseSaveGame.h`).
- Для каждого построенного объекта сервер создаёт `FGuid`, сохраняет **тип, местоположение, вращение, оставшуюся прочность и ключ владельца**.
- Данные разделены по карте: слот `NYVERRA_Bases_v1_<ИмяКарты>`; Unreal хранит их на машине сервера в `Saved/SaveGames/`.
- После запуска сервер **сначала проверяет весь файл**, затем восстанавливает акторы. При несовместимой версии, повреждённых записях или дублированных GUID файл защищён от перезаписи; новое строительство в этом режиме блокируется.
- Перезапись происходит через **3 секунды после первого изменения** (несколько последовательных изменений объединяются в одну запись). Дополнительный таймер записывает текущее состояние каждые **60 секунд**.
- При уничтожении постройки следующая запись больше не включает её. Сломанная дверь не возрождается.
- На восстановленной двери `bDoorOpen=false`: после перезапуска дверь должна быть закрыта.
- Максимум **1024 построек на карту** в схеме v1; при достижении лимита новые конструкции не создаются и материалы не списываются.
- `BuilderNetworkId` сохраняется только сервером и **не реплицируется другим игрокам**. Он извлекается из `PlayerState->GetUniqueId()`, а не из никнейма или сообщения клиента. При возвращении игрока сервер пытается снова назначить ему права.
- В одиночной игре `NM_Standalone` используется отдельный локальный идентификатор владельца для восстановления доступа без онлайн-сервиса.
- При отсутствии постоянного OnlineSubsystem ID в сетевой игре база сохраняет геометрию, но **право открытия/ремонта двери после перезапуска не восстанавливается автоматически**. Это сознательное ограничение безопасности; нужна реальная система входа.
- В режиме **Play-In-Editor (PIE)** запись на постоянный диск отключена; испытания PIE не должны перезаписывать мир сервера.

## Проверка на Windows

1. Закройте Unreal Engine / сервер.
2. Если сохранения уже есть, создайте резервную копию:
   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\Tools\Backup-NyverraBaseSaves.ps1
   ```
3. В Git-клоне запустите:
   ```bat
   git pull origin main
   TEST_ALPHA_060_WINDOWS.bat
   ```
4. При нестандартной папке UE5.8:
   ```bat
   TEST_ALPHA_060_WINDOWS.bat "D:\Epic Games\UE_5.8"
   ```
5. При успешной сборке откройте `NYVERRA.uproject` и **сохранённый уровень**. Проверка сохранения должна проходить через *Standalone Game* или реальный выделенный сервер — **НЕ через PIE**.

## Приёмочные сценарии

1. Запустить Standalone с пустым слотом; создать **1 фундамент, 1 стену, 1 дверь**. Проверить количество списанных ресурсов.
2. Получить прочность: фундамент 600 HP, стена 360 HP, дверь 280 HP. Повредить стену до 290 HP; не чинить её.
3. Подождать не менее 5 секунд и убедиться, что на сервере появился файл `Saved/SaveGames/NYVERRA_Bases_v1_<ИмяКарты>.sav`. Закрыть игру и **запустить тот же уровень снова**.
4. На прежних координатах должны восстановиться **ровно 3 постройки**, без дубликатов; стена — с оставшимися 290 HP, дверь — закрытая. Все акторы должны иметь разные GUID.
5. Разрушить дверь, подождать 5 секунд, перезапустить: дверь **не должна возвращаться**.
6. В Standalone открыть/починить сохранённую постройку как локальный владелец.
7. На двух отдельных клиентах с правильно настроенной аутентификацией OnlineSubsystem: строитель отключается и входит с **тем же ID**. Права ремонта/открытия должны восстановиться; другой игрок — без доступа.
8. При отсутствии достоверного сетевого ID проверить безопасный отказ в восстановлении прав после перезапуска — никаких никнеймов как ключа авторизации.
9. В PIE проверить, что `Saved/SaveGames` НЕ изменился.
10. Скопировать сохранение в безопасное тестовое окружение и проверить неверную версию/дублированные GUID: загрузка и запись должны блокироваться. **Не экспериментировать на единственном рабочем сохранении.**
11. Проверить приближение к лимиту 1024: новый объект не создаётся и ресурсы не списываются.
12. Проводить этот сценарий **на том же сохранённом уровне**. Текущая оригинальная пользовательская `TestWorld.umap` по предыдущим проверкам не была загружена в GitHub.

## Важные ограничения

- **Нет подтверждённой компиляции UE5.8 и реального перезапуска сервера в этой среде.** Наличие исходников и статических тестов не доказывает, что сохранение работает.
- Схема сохраняет **только постройки**, а не инвентари игроков, здоровье, ресурсы, предметы, кланы, погоду, мир и сезонные вайпы.
- Сохранения живут **на серверной машине**, Git их не хранит (папка `Saved/` в `.gitignore`). Не публиковать файлы с сетевыми идентификаторами владельцев.
- `SaveGameToSlot` использует обычную запись файлов Unreal, это **не транзакционная база данных**: внезапное отключение питания может потерять изменения после последней успешной записи. Держите резервные копии вне сервера.
- На текущем этапе для серверных прав необходим надёжный OnlineSubsystem с аутентифицированными сетевыми ID; идентификатор из незащищённого LAN/Null-провайдера недостаточен для публичного сервера.
- До релиза всё ещё нужны настоящий мир `.umap`, модели, полноценный backend, устойчивость dedicated server, система доступа к клановым базам, рейды, тестирование двух клиентов и финальная сборка Windows.
